# Единый паттерн компонентов

[Открыть справочник компонентов](index.html)

Компонент описывает поле один раз. Разметка секции задаёт имя, подпись и классы, а компонент сам подключает схему и подходящий контрол Gutenberg. Для Next и Gutenberg используем одну разметку там, где различается только способ редактирования.

## Где что лежит

| Файл | Назначение |
| --- | --- |
| `section.tsx` | Разметка секции и экземпляры компонентов. Callback в `section()` остаётся декларативным. |
| `section.json` | Идентификатор и заголовок секции. |
| `component.tsx` или `index.tsx` | Общая разметка компонента и объявление поля для компонентов Kit. |
| `editor.tsx` | Интеграция с Gutenberg, если нужен собственный контрол. |
| `schema.ts` | Явная схема для отдельных блоков. Для декларативной секции её собирает `section()`. |
| `register.php` | Регистрация отдельного блока или PHP-интеграция, если она нужна. |

## Пропсы и хуки

- `name` — ключ в сохранённых данных блока. Переименование требует переноса значений.
- `label` — подпись поля в редакторе.
- `className` — общие классы. `adminClassName` — дополнение для Gutenberg, `frontClassName` — дополнение для сайта.
- Для компонентов на `kit()` классы объединяются автоматически. В составном компоненте применяем `useClasses(props)` один раз на нужном корневом элементе.
- `initial={false}` читается внутри `Drag`: элемент остаётся в меню добавления, но отсутствует в начальной раскладке.
- `useField(name)` читает определение и значение поля, а `setValue(next)` пишет через общий контекст редактора.
- `useValues()` читает значения текущей схемы. `useFieldScope()` нужен для работы с контекстом поля и доступом к контролам редактора.
- `useSite()` читает общие настройки и коллекции. Для определения контекста редактирования поля используем `scope.edit`. `useIsEditor()` подходит для визуальных различий, которым не нужна схема.
- Для вложенного списка переиспользуем `Repeater` или `Relationship`. Дочерние элементы описывают одну строку, а её данные берутся из контекста.

## Как добавлять поля

Используем `kit(kind, describeField, render)` для обычного поля. `Object.assign(View, { kind, field })` подходит составным компонентам, которым нужно подготовить свой контекст. Декоративные компоненты и части шаблона строки не объявляют `field`. Настройку в инспекторе объявляем через `settings: true`. Существующий редактор поля лучше переиспользовать через `Field` или общий контрол; новый тип адаптируем в editor entry point.

```tsx
<ContactSocialLinks
  manual
  name="contactSocialLinks"
  className="flex flex-wrap gap-preset-20"
  adminClassName="[&>.site-record-add]:size-13"
>
  <RecordLink className="inline-flex items-center gap-preset-20">
    <RecordImage className="size-5" />
    <RecordText field="title" as="span" />
  </RecordLink>
</ContactSocialLinks>
```

Здесь секция хранит порядок и выбор соцссылок. `ContactSocialLinks` передаёт данные общему `Relationship`. `RecordLink`, `RecordImage` и `RecordText` читают текущую запись и сами полей не создают.

При изменении проверь типы, сборку редактора и сценарий сохранения. Для секций с PHP-рендером проверь также вывод WordPress. У компонентов без DOM-узла, например Choice, классам некуда применяться. Show, Toggle и RecordContent добавляют обёртку только при наличии классов. Cols передаёт классы колонке Drag.
